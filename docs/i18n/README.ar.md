تزامن خدمات iCloud Drive وDropbox وOneDrive وGoogle Drive وSyncthing الملفات واحدًا تلو الآخر. أما git فيفترض أن مجلد `.git` يتغيّر كوحدة واحدة، لذلك يتراكم في المستودع الموجود داخل مجلد متزامن نسخ تعارض مثل `.git/index 2` و`refs/heads/main 2`، وفهرس (index) مفقود بجوار `index.lock` متروك، وكائنات لا توجد إلا في السحابة. تحذّر الأسئلة الشائعة لـ git نفسه من وضع المستودعات في المجلدات المتزامنة، لكن الإعدادات الافتراضية تواصل وضعها هناك: سطح المكتب والمستندات في iCloud على macOS، ونسخ المجلدات احتياطيًا إلى OneDrive على Windows، و`Documents/GitHub`.

<p align="center">
  <img src="../../assets/sync-damage.svg" width="820" alt="عميل المزامنة ينسخ ‎.git بين الأجهزة ملفًا بملف، فيترك نسخ تعارض مثل index 2 وrefs/heads/main 2، وindex.lock بجوار فهرس مفقود، وكائنات لا توجد إلا في السحابة">
</p>

يخبرك الأمر `gitbrella check`، عادةً في أقل من ثانية، ما إذا كان المستودع يعاني هذا الضرر. صُمّم ليُشغَّل قبل أن يلمس وكيل ذكاء اصطناعي أو خطّاف (hook) لـ git المستودع. يصلح `gitbrella fix` ما له طريقة إصلاح صحيحة واحدة فقط، وينهي `gitbrella move-out` الضرر من جذوره: ينقل `.git` خارج المجلد المتزامن ويترك مكانه ملف `.git` يشير إليه، فيتولى عميل المزامنة نقل ملفاتك بينما يحتفظ git بالسجل لنفسه.

| الأمر | ما يفعله |
| --- | --- |
| `gitbrella check` | يبلّغ عن الضرر (قراءة فقط) |
| `gitbrella fix` | يصلح ما له إجابة صحيحة واحدة |
| `gitbrella move-out` | ينقل `.git` خارج المجلد المتزامن نهائيًا |
| `gitbrella undo` | يتراجع عن آخر إصلاح أو نقل |
| `gitbrella history` | يسرد التغييرات التي أُجريت على هذا الجهاز |
| `gitbrella prune-backups` | يحذف النسخ الاحتياطية القديمة لتغييرات لم يعد ممكنًا التراجع عنها |
| `gitbrella hook --for claude\|codex` | يحمي استدعاءات الأدوات لدى وكيل الذكاء الاصطناعي |

## البدء السريع

**1. الفحص.** قراءة فقط، بلا تنزيل وبلا شبكة.

```sh
cd ~/Library/Mobile\ Documents/com~apple~CloudDocs/notes
gitbrella check               # exit 0: healthy, 1: damage, 2: could not run
```

**2. الإصلاح.** لما له إجابة صحيحة واحدة فقط. بدون `--apply` يعرض الخطة فقط.

```sh
gitbrella fix                 # what it will repair and what it leaves to you
gitbrella fix --apply         # repair; `gitbrella undo --apply` puts it back
```

**3. الحل الجذري.** نقل `.git` خارج المجلد المتزامن.

```sh
gitbrella move-out            # what happens and what would stop it
gitbrella move-out --apply
```

**ابقَ محميًا.** امنع الإيداعات (commits) في مستودع متضرر:

```sh
printf '#!/bin/sh\nexec gitbrella check\n' > .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

بالنسبة إلى وكلاء الذكاء الاصطناعي، راجع [للوكلاء](#for-agents).

## ما يتعهد به

- <img src="../../assets/icons/read-only.svg" width="18" alt=""> **الأمر `check` للقراءة فقط.** لا يكتب أبدًا في المستودع. لا يشغّل git إلا أوامر القراءة، مع `GIT_OPTIONAL_LOCKS=0` وتعطيل gc التلقائي والصيانة. تسجّل الاختبارات الشاملة للحالات الخطرة (نسخة من الفهرس، فهرس مفقود، استنساخ جزئي، فهرس مقسّم، مجلد git منقول) حجم كل ملف وmtime وinode قبل الفحص وبعده، وتتحقق من تطابقها.
- <img src="../../assets/icons/no-download.svg" width="18" alt=""> **لا ينزّل شيئًا من السحابة.** على macOS يعطّل التنزيل عند الطلب لعمليته (ولـ git الذي يشغّله) قبل أن يلمس القرص؛ وإذا رفض macOS ذلك فلا يُشغَّل الفحص (رمز الخروج 2). الملف الموجود في iCloud فقط يُذكر في التقرير ولا يُجلب.
- <img src="../../assets/icons/no-network.svg" width="18" alt=""> **لا يستخدم الشبكة.** لا يجلب الاستنساخ الجزئي أبدًا الكائنات المفقودة (`GIT_NO_LAZY_FETCH`)؛ ومع إصدارات git الأقدم من 2.45 تُتخطّى فحوص الكائنات بدلًا من ذلك.
- <img src="../../assets/icons/quiet.svg" width="18" alt=""> **صامت في المستودعات السليمة.** لا يُعدّ القفل ضررًا إلا إذا كان قديمًا ولم يكن بإمكان أي git يعمل على ذلك المستودع (أيٍّ من أشجار العمل الخاصة به) أن يكون قد كتبه: ينشئ git القفل عندما يأخذه، فلا يمكن لـ git بدأ لاحقًا أن يمسكه. ملفات git المؤقتة وملفات الأدوات الأخرى داخل `.git` معلوماتية. تشغيله على 89 مستودعًا سليمًا قيد الاستخدام لم يُبلغ عن أي ضرر.

## الاستخدام

```
gitbrella check [--json] [--deep] [--provider NAME] [path]
```

رموز الخروج: **0** لا ضرر، **1** وُجد ضرر، **2** تعذّر تشغيل الفحص. وللأوامر التي تغيّر شيئًا (`move-out` و`fix` و`undo`): **0** خُطّط أو اكتمل أو لا شيء يُفعل (`already`)، **1** رُفض (مع الأسباب)، أو اكتمل مع تحذيرات، أو بقي ضرر متروك لك (قائمة MANUAL في `fix`، ويواصل `check` الإبلاغ عنه)، **2** فشل (تراجع أو توقف؛ ويحتفظ JSON بما استُعيد وبمدخلات السجل) أو تعذّر التشغيل.

يشغّل الخيار `--deep` أيضًا `git fsck` كاملًا (فهو يقرأ كل كائن، لذا يُتخطّى إذا كانت الكائنات في السحابة فقط). ويفرض الخيار `--provider` عميل المزامنة بدلًا من اكتشافه من المسار: `auto` (الافتراضي)، `icloud`، `icloud-desktop-documents`، `dropbox`، `onedrive`، `google-drive`، `syncthing`، `nextcloud`، `cloud-storage`، `none`. تُعرف مجلدات Syncthing وNextcloud (أو ownCloud) أينما كانت من خلال العلامة التي يضعها العميل داخلها (`.stfolder`، `.sync_*.db`). يقبل `fix` و`move-out` الخيار `--provider` نفسه؛ مرّر القيمة نفسها التي مرّرتها إلى `check`، لأن بعض أسماء النسخ لا تُحتسب إلا لعميل بعينه. عندها يُظهر JSON القيمة `"providerForced": true`.

### بصفته خطّافًا لـ git

```sh
#!/bin/sh
# .git/hooks/pre-commit
exec gitbrella check
```

<p align="center">
  <img src="../../assets/hook-flow.svg" width="820" alt="الأمر git commit يشغّل خطّاف pre-commit الذي يشغّل gitbrella check: عند الرمز 0 يمضي الإيداع، وعند 1 أو 2 يُحظر">
</p>

في المستودع المتضرر يُحظر الإيداع، وفي المستودع السليم يمضي كالمعتاد. تعرف الأداة أن git هو من يشغّل الخطّاف، فلا تخلط بين قفل الإيداع نفسه وقفل قديم.

**أي مستودع يُفحص.** في خطّافات الإيداع (يمرّر لها git المتغير `GIT_INDEX_FILE` أو `GIT_DIR` بمسار مطلق) يُعثر على المستودع من خلال عملية git التي شغّلت الخطّاف، لذلك يمكن للخطّاف أن يغيّر المجلد أولًا: إلى مجلد git، أو مجلد hooks الخاص به، أو مجلد خارج أي مستودع. وعندما يحدد git المستودع عبر `GIT_DIR` مطلق (شجرة عمل مرتبطة، وحدة فرعية، مجلد git منفصل)، يعمل كل أمر git داخل الخطّاف عليه أينما انتقل الخطّاف، وكذلك الفحص. وفي غير ذلك، يتحقق مما يقود إليه المجلد الحالي بالنسبة إلى git نفسه (مجلد git الذي يشير إليه `GIT_DIR` نسبي هناك، أو المستودع الذي يُعثر عليه من هناك)؛ فإذا كان مستودعًا آخر أو شجرة عمل أخرى للمستودع نفسه (خطّاف ينتقل إلى هناك، أو محرر رسالة الإيداع)، يرفض (رمز الخروج 2) بدلًا من الإجابة عن المستودع الخطأ.

من دون مسار يفحص المستودع الذي صدّره git إلى الخطّاف (`GIT_DIR`)، لذا تعمل إعدادات dotfiles التي تستخدم `--git-dir` ومجلد git الموجود داخل شجرة عمله. ومن دون مسار يتبع أيضًا `GIT_DIR` المضبوط في الصدفة (shell)؛ وبخلاف git يتجاهل `GIT_DIR` غير الموجود، ويرفض شجرة العمل المرتبطة التي لا يمكن تتبّعها بدلًا من اعتبار المجلد الحالي شجرة العمل.

**الفهرس الذي يسجّله الإيداع.** عندما يشير `GIT_INDEX_FILE` إلى ملف داخل مجلد git (وهكذا يضبطه git لخطّافات الإيداع)، فهو ما يُقرأ. وإذا كان الفهرس الذي سيسجّله الإيداع مفقودًا أو فارغًا، أو لم يعد يسرد ملفات HEAD التي ما زالت في شجرة العمل، يُحظر الإيداع قبل أن يسجّل حذف تلك الملفات. أما ملف الفهرس في مكان آخر الذي تحدده أنت عبر `GIT_INDEX_FILE` فلا يُقرأ: داخل الخطّاف يُفحص فهرس المستودع نفسه بدلًا منه، والفحص اليدوي مع ضبط هذا المتغير يُرفض (رمز الخروج 2).

**الحذف المقصود.** لإيقاف تتبّع ملفات ستبقى على القرص (`git rm --cached`، إيقاف تتبّع مجلد صار الآن متجاهَلًا)، أو لإيداع «حذف الكل» عمدًا بينما الملفات ما زالت على القرص (`git rm -r --cached .`)، تخطَّ الخطّاف باستخدام `git commit --no-verify`.

### مع مدير خطّافات

- **pre-commit** ‏(pre-commit.com): أضف هذا المستودع بمعرّف الخطّاف `gitbrella` (يبنيه pre-commit بلغة Go) أو `gitbrella-system` (الملف التنفيذي الموجود في PATH)؛ راجع `.pre-commit-hooks.yaml`.
- **lefthook**: استورد `hooks/lefthook.yml` عبر `remotes`.
- **husky**: ملف `.husky/pre-commit` يحتوي على `gitbrella check`.
- **Overcommit**: ‏`PreCommit: { Gitbrella: { enabled: true, required_executable: gitbrella, command: [gitbrella, check] } }`، ثم `overcommit --sign`.

في جميعها يوقف أي رمز خروج غير صفري الإيداع، لذلك فإن الفحص الذي تعذّر تشغيله (رمز الخروج 2) يوقفه أيضًا. يودِع Aider باستخدام `--no-verify` ما لم يُضبط `git-commit-verify: true`، وعندها لا يُشغَّل أي خطّاف إيداع على الإطلاق. يودِع Obsidian Git (نسخة سطح المكتب) باستخدام git الموجود على نظامك ويشغّل الخطّاف؛ ضع المجلد الذي يحتوي `gitbrella` في إعداده «Additional PATH»، لأن التطبيقات التي تُفتح من Dock لا تتلقى PATH الخاص بالصدفة. أما Obsidian Git على الهاتف (isomorphic-git) فلا يشغّل أي خطّافات.

<a name="for-agents"></a>

### للوكلاء

يطبع الخيار `--json` التقرير نفسه كمستند مستقر ذي إصدار (`schemaVersion: 1`، و`findings` قائمة دائمًا). اتخذ القرار بناءً على رمز الخروج، واعرض النتائج على المستخدم.

خطّافات الوكلاء نفسها لا توقف استدعاء الأداة إلا عند رمز الخروج 2: الرمز 1 («وُجد ضرر») يسمح للاستدعاء بالمضي. يتحدث `gitbrella hook --for claude|codex` بلغة خطّافاتهم. يقرأ الحدث الذي يمرّره الوكيل عبر stdin:

<p align="center">
  <img src="../../assets/agent-hook.svg" width="820" alt="استدعاء أداة الوكيل يمرّ عبر gitbrella hook: القراءة والتحرير يمضيان؛ وفي المستودع المتضرر تتوقف كتابات git والكتابة داخل ‎.git‎ برمز الخروج 2">
</p>

- **قبل استدعاء الأداة** (`PreToolUse`): في المستودع المتضرر، يوقف الاستدعاءَ أيُّ أمر git يكتب (commit وadd وreset وrebase وpush وأي شيء غير معروف أنه يقرأ فقط) وأيُّ كتابة داخل `.git` (رمز الخروج 2، والسبب في stderr للوكيل). القراءة وتحرير ملفاتك و`git restore` و`gitbrella` نفسه تمضي، حتى يمكن فحص الضرر وإصلاحه.
  - *المستودعات غير الصالحة للاستخدام.* حيث تكون ملفات git في السحابة فقط، أو لا يستطيع git استخدام المستودع إطلاقًا (`HEAD` أُعيدت تسميته، ملف `.git` يشير إلى لا مكان)، يتوقف كل أمر git: فهو إما سيتجمد أو سيعمل على مستودع خارجي. وتمضي هناك الكتابات داخل `.git`: فذلك الإصلاح يُجرى يدويًا داخل `.git` كما يقول السبب (`mv '.git/HEAD 2' .git/HEAD`). كما يمضي العلاج الذي يسمّيه تلميح `core.worktree` ‏(`git config --file … --unset core.worktree`).
  - *أي مستودع.* المستودع الذي يحتوي الملفات التي يعمل عليها الاستدعاء (رقعة Codex تسمّي ملفاتها؛ والمسار داخل `.git` يُحتسب لشجرة العمل التي فوقه). وبالنسبة إلى أمر الصدفة: مجلد الجلسة وكل مجلد تعمل فيه أوامر git الخاصة به (`cd DIR`، `pushd`، `git -C DIR`، `--git-dir`، `--work-tree`، `GIT_DIR`، `env -C`، `bash -c '…'`)، الكاتبة أولًا، وخمسة على الأكثر؛ وعندما لا يتسع مجلد كاتب، يمرّ الاستدعاء مع تنبيه. يُحكم على كل مجلد بما يفعله الاستدعاء فيه: `git -C ../sound commit` من مجلد جلسة متضرر يمضي. والمجلد الذي ليس مستودعًا والمستودع العاري (bare) يمرّان بصمت.
  - *عندما يتعذّر تشغيل الفحص.* أي شيء يمنع الفحص من العمل (بما في ذلك `--timeout` البالغ 20 ثانية، وهو موعد نهائي واحد للاستدعاء كله) يمرّر الاستدعاء مع تنبيه؛ ويفعل `--fail-open` الشيء نفسه حيث لا يستطيع git استخدام المستودع.
  - *كيف يُقرأ الأمر.* يُقرأ ولا يُنفَّذ أبدًا: علامات الاقتباس، والتعليقات، والصدفات الفرعية، والاستبدالات (بما فيها داخل heredoc غير مقتبس)، وheredoc، والمتغيرات التي يضبطها، و`&&` و`||` و`if` و`case` والحلقات (بعد `cd a || cd b` أو `cd` إلى مجلد غير موجود، يُحتسب كل مجلد قد تكون فيه الصدفة؛ وتُقرأ حلقة `for` مرة لكل قيمة)، والأغلفة (`timeout` و`sudo` و`nice` و`xargs` و`env`)، والسكربتات الممرَّرة إلى صدفة (`-c` و`eval` و`watch` و`source` وملف وheredoc و`bash < f` وأنبوب إلى `sh`). الدوال والأسماء المستعارة التي يعرّفها الأمر تُقرأ حيث تُستدعى. وسكربت الصدفة الذي يُشغَّل بمساره أو يُمرَّر إلى صدفة (`./deploy.sh`، `bash deploy.sh`) يُقرأ إذا كان ملفًا صغيرًا على هذا الجهاز (حتى عبر رابط رمزي؛ ومرة واحدة حتى لو شغّل نفسه)؛ أما `make` و`npm run` وما شابههما فلا تُقرأ.
  - *ما يُعدّ كتابة.* كتابة برنامج آخر داخل `.git` (`rm .git/index.lock`، `> .git/HEAD`، `cd .git && rm index.lock`، `sed -i` على `.git/config`، `rm -rf` أو `find -delete` على مجلد يحتوي `.git`، رقعة Codex عبر الصدفة) تُعدّ كتابة داخل `.git`؛ أما نسخ `.git` إلى مكان آخر، أو أرشفته بـ`tar`، أو قراءته فلا. ويُعدّ `gh pr checkout` و`git-lfs` أوامر git كاتبة.
  - *عند الشك.* يُعدّ كلٌّ مما يلي أمر git كاتبًا: قراءة تتجاوز 5000 خطوة أو نصف `--timeout` (في المجلد الذي تعذّر تحديده)؛ وكلمة `git` في موضع لا تتبعه القراءة؛ وسكربت يُمرَّر بأنبوب إلى صدفة من برنامج لا تتبعه القراءة (`curl … | sh`)، حيث يعمل؛ وسكربت موجود لكن لا يمكن قراءته يُمرَّر إلى صدفة (كبير جدًا، في السحابة فقط)، حيث يعمل. وعندما يتعذّر تحديد المجلد الذي يكتب فيه أمر git ‏(`cd "$(…)"`، `for d in */`)، يُحتسب الأمر في كل مجلد يُفحص، ويحصل الاستدعاء على تنبيه.
- **عند بدء الجلسة** (`SessionStart`): سطر واحد على stdout يقرؤه الوكيل كسياق، يقول إن المستودع داخل مجلد متزامن (ما لم يكن مجلد git الخاص به قد نُقل للخارج بالفعل) وما المتضرر. لا يحظر أبدًا.

لا يغيّر الخطّاف شيئًا. لـ Claude Code، في `.claude/settings.json`:

```json
{
  "hooks": {
    "SessionStart": [{"hooks": [{"type": "command", "command": "gitbrella hook --for claude"}]}],
    "PreToolUse": [{"matcher": "Edit|Write|MultiEdit|NotebookEdit|Bash",
                    "hooks": [{"type": "command", "command": "gitbrella hook --for claude"}]}]
  }
}
```

لـ Codex، في `.codex/hooks.json` (لا يشغّل Codex الخطّاف إلا بعد أن تثق به في `/hooks`):

```json
{
  "hooks": {
    "SessionStart": [{"hooks": [{"type": "command", "command": "gitbrella hook --for codex"}]}],
    "PreToolUse": [{"matcher": "Bash|apply_patch",
                    "hooks": [{"type": "command", "command": "gitbrella hook --for codex"}]}]

```

يعمل الفحص مرة لكل واحد من هذه المجلدات، عادةً من 0.1 إلى 0.4 ثانية لكل منها، لذا فإن الرقعة الموزعة على عدة مجلدات من مستودع واحد تفحص ذلك المستودع عدة مرات؛ ويحدّ `--timeout` من زمن الاستدعاء كله.

<a name="repairing"></a>

## الإصلاح

```sh
gitbrella fix                 # what it will repair and what it leaves to you
gitbrella fix --apply         # repair
gitbrella undo --apply        # put everything back
gitbrella history             # changes made here, their backups and sizes
gitbrella prune-backups       # backups no undo will need any more
```

<p align="center">
  <img src="../../assets/fix-flow.svg" width="820" alt="fix يعرض الخطة؛ fix --apply يسجّل كل خطوة ثم يُعاد الفحص: اكتمل أو تراجع؛ undo --apply يتراجع عن آخر تغيير">
</p>

يذكر `check` تحت كل ضرر ما إذا كان `fix` يصلحه (`repair:`، و`"repair": "fix"` أو `"manual"` في JSON)، ويسمّي `fix --provider NAME` عندما يكون قد مُرِّر مزوّد إلى الفحص. لا يسأل داخل خطّافات الإيداع.

لا يصلح `fix` إلا حيث توجد إجابة صحيحة واحدة ولا يُكتب فوق أي شيء ربما قصدته:

| الضرر | الإصلاح |
| --- | --- |
| نسخ التعارض في `.git` بجوار أصلها (`HEAD 2`، `refs/heads/main 2`، `refs 2`، `packed-refs 2`، نسخ Dropbox وSyncthing، ونسخة قفل مرجع مثل `refs/heads/main 2.lock`)؛ ونسخة الفهرس فقط إذا كانت مطابقة تمامًا للفهرس أو كانت فهرسًا صالحًا يساوي HEAD | تُنقل إلى نسخة احتياطية؛ والكائن (إيداع أو وسم أو شجرة أو ملف) الذي لا تشير إليه إلا النسخة يُحفظ أولًا باسم `refs/gcd-rescue/<name>` |
| مجلد rebase متروك، و`desktop.ini` و`Icon` وملفات مشابهة لم ينشئها git (ما لم يقرأ git أحدها كفرع أو كان اسمه اسم كائن)، ونسخة من `.git` في شجرة العمل يملك المستودع إيداعاتها | تُنقل إلى نسخة احتياطية |
| فهرس مفقود ليست له نسخة ولا قفل في أي مكان | يُنشأ من HEAD ‏(`git read-tree HEAD`: لا تُلمس الملفات)، فقط إذا وُجد إيداع يُبنى عليه (إذا كان إيداع HEAD مفقودًا أيضًا يُجلب أولًا كما هو موضح أدناه) وخارج sparse checkout |
| فهرس لا يسرد أي ملف (فهرس صالح غير مقسّم، خارج sparse checkout) | يُنقل إلى نسخة احتياطية ويُنشأ من HEAD: لم يكن فيه شيء مُجهَّز للإيداع |
| `index.lock` يتيم هو فهرس صالح يساوي HEAD | يصبح هو الفهرس |
| ملف فرع فارغ | الإيداع الذي سجّله سجل المراجع (reflog) الخاص به آخر مرة |
| `.git.nosync` الذي كان git سيضيفه إلى إيداع | السطر `/.git.nosync/` في `.git/info/exclude` |
| إيداع HEAD مفقود، أو ملف كائن loose فارغ (بلا نسخة بجواره) | يُنقل الملف الفارغ إلى نسخة احتياطية وتُجلب الكائنات من جديد (`git fetch --refetch`، git 2.36 أو أحدث) من `--remote`، وإلا من الريموت الخاص بالفرع، وإلا من `origin`، وإلا من الريموت الوحيد؛ تُجلب فروع الريموت ووسومه إلى مساحة أسماء مؤقتة `refs/gcd-fetch/` تُحذف بعد ذلك، فلا يتغير أي مرجع. وإذا لم يُعِد الريموت الكائن، يُتراجع عن الإصلاح |
| مع `fix --deep`: الكائنات التي أبلغ `git fsck` عن تضررها | يُجلب كل كائن من فروع الريموت ووسومه بالطريقة نفسها؛ ثم يُعاد تشغيل `git fsck`، وإذا ظل يُبلغ عن أخطاء (كائن لا يملكه أي ريموت، ملف تالف باقٍ) يُتراجع عن الإصلاح |
| نسخ التعارض لملفاتك أنت (`notes 2.md`) التي لا يتتبعها git وتحمل البايتات نفسها للملف الذي نُسخت منه | تُنقل إلى نسخة احتياطية (كان `git add -A` سيودعها)؛ أما النسخة المختلفة أو المتتبَّعة أو التي هي رابط أو في السحابة فقط أو داخل وحدة فرعية فتبقى |
| `gc.pid` لجهاز آخر أقدم من ساعة؛ و`gc.log` | يُنقلان إلى نسخة احتياطية، فيعمل gc التلقائي لـ git هنا من جديد |
| ملفات `.git` أو مخزن كائنات بديل الموجودة في السحابة فقط | تُنزَّل، ولا شيء غير ذلك: حتى ذلك الحين لا يستطيع الفحص قراءة الكائنات، لذا يُدرج الضرر المتبقي كـ MANUAL حتى تشغيل `fix` التالي |

كل ما عدا ذلك يُدرج كـ MANUAL مع الأمر الذي يجب تشغيله. ويشمل ذلك كل ما قد يحتوي عملًا غير موجود في أي مكان آخر:
- فهرس تالف (قد يظل git قادرًا على قراءته مع العمل المجهّز)؛
- نسخة من الفهرس أو `index.lock` تختلف عن HEAD، ونسخة من `index.lock`؛
- نسخة أصلها مفقود (قد تكون الوحيدة: أعِدها إلى مكانها؛ وإن كانت نسخة قفل فتُحفظ وتُنحّى جانبًا)؛
- قفل لا يمسكه أي git على هذا الجهاز (قد يمسكه git على جهاز آخر أو في حاوية؛ وتسمّي النصيحة الإيداع الموجود فيه)؛
- نسخة تسمّي أكثر من 100 كائن (سجل مراجع طويل)؛
- نسخة من الفرع الذي يسمّيه أي HEAD، أو من سجل مراجعه، أو من مجلد يحتويه (يقرؤها git مهما بدا اسمها).

وكل ما كان على fix فيه أن يختار بين نسختين أو لا يستطيع إبقاء إيداعات النسخة حيّة:
- كل ما في مخزن الكائنات: النسخ، والملفات التي تحمل اسم كائن (تحقق أيّها يطابق تجزئته)، وملفات الكائنات الفارغة التي لا ريموت لجلبها منه؛
- كل ما في مجلد git لوحدة فرعية (شغّل `fix` داخل الوحدة الفرعية)؛
- نسخة فرع تسمّي إيداعًا لم يصل إلى هنا بعد (قد يصل لاحقًا)؛
- نسخة من `.git` في شجرة العمل تحتوي إيداعات يفتقدها المستودع (أنت من يقرر أيّها الحالية)؛
- ملف فارغ بجواره نسخة منه أو من مجلده؛
- مجلد إدارة تالف لشجرة عمل مرتبطة (`git worktree repair`)؛
- فهرس فقد ملفات ما زالت على القرص (إيقاف التتبع المقصود يبدو بالشكل نفسه؛ وعندما لا يكون هناك شيء آخر مجهّز، تقول النصيحة إن `git read-tree HEAD` يعيدها دون فقدان أي شيء)؛
- بدون `--deep` أو بدون ريموت: الكائنات التي أبلغ `git fsck` عن تضررها.

لا يلمس `fix` مستودعات reftable إطلاقًا؛ وهناك تخبرك نتيجة `REFTABLE_TABLE_UNLISTED` من `check` بكيفية الحفاظ على مراجع جهاز آخر. يجب أن تكون النسخة الاحتياطية على قرص المستودع، حتى يُنقل ما ينحّيه fix جانبًا في خطوة واحدة؛ وإلا يرفض `fix` (الإصلاح الذي يقتصر على التنزيل لا ينقل شيئًا ولا يحتاج إلى ذلك).

تُسجَّل كل خطوة قبل تنفيذها، وفي النهاية يُعاد الفحص: إذا ظل شيء أصلحه يُبلَّغ عنه، أو ظهر ضرر جديد، يُتراجع عن الخطوات. والإصلاح الذي قُطع يُتراجع عنه بواسطة أمر التغيير التالي الذي يُشغَّل مع `--apply` في ذلك المستودع، ثم يتوقف ذلك الأمر؛ شغّله مرة أخرى. وبعد 30 ثانية (`--watch`) يفحص `fix` مرة أخرى: الضرر الذي عاد أعاده عميل المزامنة، والعلاج الدائم هو `move-out`.

يتراجع `undo` عن أحدث تغيير أولًا، سواء كان إصلاحًا أو نقلًا. الخطوة التي تغيّرت نتيجتها منذ الإصلاح تُترك كما هي وتُدرج، ولا يُكتب فوقها أبدًا: أعاد git كتابة الفهرس المُعاد إنشاؤه، أو أعاد عميل المزامنة نسخة، أو تحرّك مرجع إنقاذ، أو حُذفت النسخة الاحتياطية، أو نُقل `.git`. يبقى مرجع الإنقاذ ما دامت النسخة التي يبقيها حيّة موجودة في النسخة الاحتياطية. تبقى الملفات المنزّلة على القرص، وتبقى الكائنات المجلوبة من جديد في مخزن الكائنات: لا يحلّ أيّ منهما محل أي شيء. ويُتراجع عن الباقي ويكتمل undo، فيمكن بعدها التراجع عن التغيير الذي سبقه.

يسرد `history` التغييرات التي أجراها هذا الجهاز على المستودع (الإصلاحات وعمليات النقل والتراجع)، والنسخة الاحتياطية التي يحتفظ بها كل منها مع حجمها، وأيّها سيتراجع عنه `undo` تاليًا. ويحذف `prune-backups`، مع `--apply` فقط، النسخ الاحتياطية للتغييرات التي تم التراجع عنها أو عكسها أو التي لم يكن ممكنًا التراجع عنها أصلًا (undo أو prepare أو attach) والتي آخر خطوة فيها أقدم من `--older-than` (الافتراضي `720h`). والإصلاح أو النقل الذي ما زال يمكن التراجع عنه يحتفظ بنسخته الاحتياطية، حتى لو كانت فوقه تغييرات أحدث.

<a name="moving-git-out-of-the-synced-folder"></a>

## نقل ‎.git‎ خارج المجلد المتزامن

```sh
gitbrella move-out            # what happens and what would stop it
gitbrella move-out --apply    # do it
gitbrella undo --apply        # move it back
```

<p align="center">
  <img src="../../assets/move-out.svg" width="860" alt="قبل: ‎.git‎ داخل المجلد المتزامن. بعد move-out: ملف ‎.git‎ في المجلد المتزامن يشير إلى ~/.local/share/gitbrella/gitdirs/notes-1a2b3c4d في الخارج">
</p>

ينسخ `move-out` المجلد `.git` إلى `~/.local/share/gitbrella/gitdirs/<name>` (على macOS نسخة APFS لا تشغل مساحة)، ويثبت ملفًا بملف أن النسخة مطابقة، وينقل الأصل إلى نسخة احتياطية تحت `~/Library/Application Support/gitbrella` (على Linux: ‏`$XDG_STATE_HOME/gitbrella`)، ويكتب ملف `.git` مثل `gitdir: ../../../../.local/share/gitbrella/gitdirs/notes-1a2b3c4d`. المسار نسبي، لذا فإن كل جهاز يحتفظ بالمجلد في المكان نفسه تحت مجلد المنزل يكتب ملف `.git` نفسه. ثم يتحقق من أن git يجد HEAD نفسه والحالة نفسها والإعدادات نفسها ومجلد hooks نفسه، ويراقب لمدة 30 ثانية (`--watch`) أن عميل المزامنة لا يلمس `.git`، وأنه في iCloud يرفع الملف الجديد. يُنحّى الأصل جانبًا قبل المقارنة النهائية، لذا فإن أي كتابة تسللت أثناء النسخ تُكتشف ويُتراجع عن النقل. في iCloud يرفض `move-out` العمل ما دام iCloud ما زال يرفع المستودع؛ أما `--wait-upload 10m` فينتظر حتى تلك المدة بدلًا من ذلك.

يُسجَّل كل تغيير في سجل (journal) قبل حدوثه، مع الجهاز وinode لكل ما ينشئه (وبايتات ملف `.git`)؛ ولا يلمس التراجع أي شيء آخر. إذا توقفت العملية في المنتصف، فإن `move-out --apply` التالي (أو `undo --apply`) يُكملها أو يتراجع عنها ثم يتوقف هناك (شغّل الأمر مرة أخرى للمتابعة)؛ ويُعثر على التغيير غير المكتمل من خلال inode المجلد، حتى لو كُتب المسار بطريقة أخرى، أو بعد إعادة تسمية، أو داخل مستودع آخر. وفي الأثناء يُبلّغ `check` عن التغيير غير المكتمل كضرر. لا يُتراجع عن أي شيء فوق المجلد المنقول بعد أن يبدأ git باستخدامه: إذا احتوى على شيء غير موجود في الأصل، يتوقف الأمر ويسمّي الاثنين. لا يُحذف شيء: يبقى الأصل في النسخة الاحتياطية حتى تزيله أنت. يعيد `undo` مجلد git المستخدم حاليًا، مع الإيداعات التي أُجريت بعد النقل؛ وتُترك النسخة الاحتياطية السابقة للنقل كما هي. وإذا كان عميل المزامنة قد أخلى ملف `.git` (لم يبقَ منه على هذا الـ Mac إلا اسمه)، فإن `undo` والاستعادة يطلبان منك تنزيله أولًا: فقراءته ستؤدي إلى تنزيله، وهذه الأداة لا تفعل ذلك أبدًا.

إذا وجد التراجع كلًّا من الأصل (في النسخة الاحتياطية) و`.git` جديدًا (أنشأته أنت أو عميل المزامنة بعد توقف النقل)، فلا يكتب فوق أيٍّ منهما ويخبرك بذلك: قارن بينهما، وانقل `.git` الذي لا تريده خارج المجلد، وشغّل الأمر مرة أخرى.

يرفض (رمز الخروج 1، مع الأسباب) ما دام git أو أي شيء يمسك قفلًا لـ git يعمل على المستودع، وأثناء merge أو rebase، وما دامت ملفات `.git` في السحابة فقط، وما دام iCloud ما زال يرفع المجلد، وما دام في `.git` مقبس (socket) (‏`git fsmonitor--daemon` قيد التشغيل)، وعندما يوجد مجلدا git بعد نقل، ولتخطيطات ستنكسر روابطها: أشجار العمل المرتبطة، والوحدات الفرعية، والكائنات المستعارة (`alternates`)، و`.git` الذي هو رابط رمزي أو ليس مجلد git نفسه. أما الأضرار الأخرى التي وجدها `check` فتُنقل كما هي وتُدرج على أنها مُرحَّلة: شغّل `check` مرة أخرى بعد ذلك.

### الأجهزة الأخرى

يحذف عميل المزامنة `.git` على كل جهاز آخر يزامن المجلد، ويوصل ملف `.git` بدلًا منه. للحفاظ على سجلها:

<p align="center">
  <img src="../../assets/other-devices.svg" width="820" alt="1: ‏move-out --prepare --apply على كل جهاز آخر. 2: ‏move-out --apply على جهاز واحد. 3: ‏move-out --attach --apply على كل جهاز آخر">
</p>

1. على كل جهاز آخر، قبل النقل: ينسخ `gitbrella move-out --prepare --apply` مجلد `.git` الخاص بذلك الجهاز إلى المكان الذي سيشير إليه ملف `.git`.
2. على جهاز واحد: `gitbrella move-out --apply`.
3. على كل جهاز آخر، بعد وصول ملف `.git`: ‏`gitbrella move-out --attach --apply`. أما الجهاز الذي لم يُجهَّز فيستنسخ السجل بدلًا من ذلك: ‏`--attach --from <remote URL> --apply`. وفي كلتا الحالتين لا تُلمس شجرة العمل.

يصل ملف `.git` عبر عميل المزامنة، لذا لا يثق به attach إلا بالقدر الذي تسمح به سجلات هذا الجهاز: يجب أن يشير إلى داخل `~/.local/share/gitbrella/gitdirs` على هذا الجهاز، والمجلد الموجود هناك مسبقًا لا يُستخدم إلا إذا كان `--prepare` قد أنشأه لهذا المستودع.

من الآن فصاعدًا ينقل عميل المزامنة الملفات لا السجل. شارك الإيداعات عبر ريموت. وعلى جهاز سبق أن حدّث عميل المزامنة ملفاته، يرفض `git pull` ‏(«would be overwritten»): استخدم `git fetch` ثم `git reset --mixed @{u}`، الذي يحرّك الفرع والفهرس ويترك الملفات المتزامنة كما هي.

عندما لا يكون المسار مستودعًا على الإطلاق، يذكر السبب إن كان على القرص: `.git 2` أُعيدت تسميته، أو ملفات git نفسه في السحابة فقط، أو مجلد git بلا HEAD، أو ملف `.git` يشير إلى مجلد git لم يعد موجودًا، أو `core.worktree` يشير إلى مجلد غير موجود على هذا الجهاز (إعداد جهاز آخر جلبه عميل المزامنة). وإذا كان في المسار `.git` لا يستطيع git استخدامه، يتوقف هناك (رمز الخروج 2) بدلًا من الإجابة عن مستودع خارجي كما يفعل git نفسه.

<a name="install"></a>

## التثبيت

يتطلب git 2.31 أو أحدث. يعمل على macOS وLinux، بمعماريتي amd64 وarm64، بلا cgo.

```
brew install aliyilmazco/tap/gitbrella
```

```
go install github.com/aliyilmazco/gitbrella/cmd/gitbrella@latest
```

أو نزّل أرشيفًا من صفحة الإصدارات (releases).

### التحقق من إصدار

يأتي كل إصدار مع `checksums.txt` (‏SHA-256 لكل أرشيف ولكل SBOM)، وتوقيع cosign بلا مفاتيح `checksums.txt.sigstore.json` يصنعه سير عمل الإصدار، وSBOM بصيغة SPDX لكل أرشيف، وشهادة مصدر البناء من GitHub ‏(build-provenance attestation). تحقق من التوقيع أولًا، ثم من الأرشيف مقابل القائمة الموقّعة (المثال هو v1.2.3 لمعالجات Apple silicon). استخدم cosign v3.1.3 أو أحدث (v2.6.5 في سلسلة v2): يمكن خداع الإصدارات الأقدم بحزمة مزوّرة (GHSA-fx35-mq7g-6g98).

```sh
cosign verify-blob \
  --certificate-identity 'https://github.com/aliyilmazco/gitbrella/.github/workflows/release.yml@refs/tags/v1.2.3' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  --bundle checksums.txt.sigstore.json checksums.txt
grep ' gitbrella_1.2.3_darwin_arm64.tar.gz$' checksums.txt | shasum -a 256 -c
gh attestation verify gitbrella_1.2.3_darwin_arm64.tar.gz \
  --repo aliyilmazco/gitbrella \
  --signer-workflow aliyilmazco/gitbrella/.github/workflows/release.yml \
  --source-ref refs/tags/v1.2.3 --deny-self-hosted-runners
```

يُبنى الإصدار من وسم مدفوع بواسطة `.github/workflows/release.yml` باستخدام `.goreleaser.yaml`، ويبقى مسودة حتى ينشره شخص ما. تُبنى الملفات التنفيذية باستخدام `-trimpath` ووقت الإيداع، لذا فإن الوسم نفسه وإصدار Go نفسه (يأخذ سير العمل أحدث تصحيح من 1.26) يبنيان الملفات التنفيذية نفسها؛ أما الأرشيفات وملفات SBOM المحيطة بها فتحمل أوقات بنائها.

<a name="limits"></a>

## الحدود

- لا يصلح `fix` إلا حيث توجد إجابة صحيحة واحدة، ويترك الباقي لك مع الأمر الذي يجب تشغيله؛ والعلاج الدائم هو `move-out`، الذي يُبقي `.git` خارج المجلد المتزامن.
- لم تُستنسخ في الاختبارات نسخ التعارض التي ينشئها iCloud نفسه بين جهازين؛ واختُبر الاكتشاف على نسخ تتبع التسمية نفسها.
- لا يمرّر Codex قيمة `workdir` الخاصة بأداة الصدفة إلى الخطّافات: الأمر الذي يشغّله Codex في مجلد آخر يُفحص في مجلد الجلسة.
- لم يُختبر على Windows ولا OneDrive على Windows. تحصل مستودعات reftable على الفحوص على مستوى الملفات وعلى فحص الجداول غير المدرجة؛ ولا تُقارن فيها نسخ المراجع بفروعها.
- أسماء النسخ ذات العلامات التي قد يحملها اسم عن قصد لا تُطابَق إلا حيث ينشئ git الاسم بنفسه، وليس أبدًا في شجرة العمل: `index (1)` من Google Drive لملفات git نفسه وداخل `refs/`؛ و`index-COMPUTER` من OneDrive لملفات git نفسه في المستوى الأعلى من مجلد OneDrive، باسم جهاز يحتوي حرفًا كبيرًا، وليس كلمة يُختم بها اسم نسخة احتياطية عادةً (`index-old` و`config-OLD` و`config-Backup` و`index-BAK` لك)، وبطول 15 حرفًا على الأكثر (يُفوَّت اسم Mac أطول)؛ و`_conflict-YYYYMMDD-HHMMSS` من Nextcloud القديم، وأسماء Synology Drive، و`.conflicted` من pCloud، و`.Conflict` من Resilio لملفات git نفسه في المستوى الأعلى (أسماء Nextcloud القديم أيضًا في `refs/` و`logs/` بجوار الأصل في مجلد Nextcloud). الفرع الذي يسمّيه أي HEAD (بصيغة `ref:` مع أي مسافات، أو كرابط رمزي)، وسجل مراجعه، والمجلدات التي تحتويه، لا تُنحّى جانبًا أبدًا مهما كانت أسماؤها. لذلك فإن `report (1).pdf`، أو فرعًا باسم `fix.Conflict`، أو وسمًا باسم `v1.0.conflicted`، أو `config-backup` أسماء عادية.
- تُفحص الوحدات الفرعية من داخل الوحدة الفرعية. ومن المشروع الأب، لا يُبلَّغ عن نسخة تعارض في `.git/modules/<name>/` إلا عندما يكون أصلها بجوارها، ويُبلَّغ عن الوحدة الفرعية المسمّاة كنسخة (`lib 2`) على أنها نسخة.
- يُبلَّغ عن الفهرس المفقود لشجرة عمل مرتبطة عند فحص تلك الشجرة، لا الشجرة الرئيسية.
- عندما يكون `.git` رابطًا رمزيًا إلى مخزن خارج المجلد المتزامن، شغّل git والفحص من شجرة العمل المرتبطة. فمن مجلد المخزن، الذي لا يحتوي أي ملف، يبدو الفهرس الذي أُفرغ كـ«حذف الكل» مقصود ولا يحظر الإيداع.
- بعض الإيداعات المقصودة تحتاج إلى `--no-verify`: إيقاف تتبع ملفات تبقى على القرص، وحذف كل ملف حيث يجب ألّا تُقرأ الكائنات، وإعادة تسمية لا تغيّر إلا حالة الأحرف أو صيغة Unicode لملف له رابط صلب آخر، وأي إيداع في sparse checkout (بنمط cone أو بدونه) يزيل ملفًا متتبَّعًا أو يعيد تسميته أو ينقله عبر تغيير النوع (ملف صار مجلدًا، أو مجلد صار رابطًا رمزيًا أو وحدة فرعية). فهناك تقرر أنماط sparse في git أي الملفات على القرص، لذا لا يمكن تمييز الإزالة المقصودة من الفهرس المفقود؛ ولا تُقرأ الأنماط.
- إذا فقد عميل المزامنة مرجع الفرع نفسه مع الفهرس (حُذف ملفه loose قبل وصول `packed-refs` جديد)، يبدو HEAD كفرع جديد ولا يُحظر الإيداع: يبدأ سجلًا جديدًا لا يحتوي إلا الملفات المجهّزة. لا يُحذف شيء من القرص، ويبقى السجل القديم في سجل المراجع (`git reflog`).
- مع الفهرس المقسّم، أو حيث يجب ألّا تُقرأ الكائنات (الاستنساخ الجزئي مع git أقدم من 2.45، والمخازن البديلة الموجودة في السحابة فقط)، لا يُقارن الفهرس بـ HEAD ملفًا بملف: لا يُكتشف إلا الفهرس المفقود أو الفارغ.
- مع `core.splitIndex`، لا يُتعرّف على الفهرس الذي لا يسرد أي ملف (رأسه لا يحصي إلا الجزء المقسّم)، لذا لا يُحظر الإيداع منه.
- الخطّافات: خطّافات الإيداع وحدها يُعثر عليها من خلال عملية git التي تشغّلها. أما الخطّافات الأخرى (`pre-push`، `pre-applypatch`) فيجب أن تشغّل الفحص من شجرة العمل، وإلا تُرفض (رمز الخروج 2). وحيث لا تكون عملية git مرئية (عميل يشغّل الخطّافات بنفسه، أو سرد عمليات محظور)، يعود الفحص إلى المجلد الحالي: وعندها، إذا لم يكن مجلد git يشير إلى شجرة العمل (`--separate-git-dir`، `.git.nosync`، `--work-tree`)، فإن الفهرس الخالي من الملفات يحظر الإيداع دائمًا (استخدم `--no-verify` للإفراغ المقصود)، والمجلد الحالي الذي لا يحتوي أي ملف من HEAD لا يُفحص كشجرة عمل (`WORKTREE_GUESSED`)، والخطّاف الذي ينتقل إلى مستودع آخر أو مجلد git يُرفض (رمز الخروج 2). خطّافات الاستقبال (`pre-receive`) ليست بوابة مدعومة.
- `move-out`: لا تفهم كل الأدوات ملف `.git`. يعمل git والأدوات التي تشغّل git؛ ولا يعمل isomorphic-git (‏Obsidian Git على الهاتف) ولا الأدوات التي تفتح `.git` كمجلد.
- `move-out`: إعادة تسمية المجلد المتزامن أو نقله تكسر ملف `.git` النسبي. عندها يسمّي `check` المجلد المفقود؛ أعِد المجلد إلى مكانه أو وجّه ملف `.git` يدويًا إلى مجلد git.
- يتطلب `move-out` أن يكون المجلد المتزامن في المكان نفسه تحت مجلد المنزل على كل جهاز (وهذا دائمًا حال iCloud Drive؛ أما Dropbox فقد يكون `~/Dropbox` على جهاز و`~/Library/CloudStorage/Dropbox` على آخر). وعندما لا يكون كذلك، يشير ملف `.git` هناك إلى مكان آخر ويرفض `--attach` ‏(`TARGET_UNEXPECTED`).
- يوجد مجلد git المنقول على نظام ملفات مجلد المنزل؛ ولا يوجد خيار لوضعه في مكان آخر.
- ينسخ `move-out --prepare` سجل الجهاز كما هو في تلك اللحظة: انقل بعد التجهيز بقليل، دون إيداعات جديدة بينهما.
- جُرّب `move-out` و`fix` في مجلد iCloud Drive نفسه، لا داخل مجلد iCloud الخاص بتطبيق (‏`iCloud~md~obsidian` الخاص بـ Obsidian).
